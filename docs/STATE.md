# GymTracker — состояние проекта

Приложение по спецификации `docs/gym-tracker-requirements.md` (MVP, релиз 1).
Версия 1.0.3 (`versionCode = 5`). Kotlin + Jetpack Compose + Room, офлайн,
только кг, только русский, тёмная тема по умолчанию. Единственное сетевое
обращение — проверка обновлений по кнопке в настройках.
Изменения по версиям — `docs/CHANGELOG.md`, мокапы — `docs/mockups-mvp.html`,
сборка — `docs/BUILD.md`, выпуск релиза — `docs/RELEASE.md`.

## Как открыть и собрать

1. Открыть папку проекта в Android Studio (File → Open). Gradle wrapper лежит
   в репозитории целиком (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`
   и `gradle-wrapper.properties`, Gradle 8.7): он сам скачает дистрибутив,
   устанавливать Gradle не нужно.
2. Создать `secrets.properties` в корне проекта (шаблон — `secrets.properties.example`)
   и указать `applicationId=…`. Идентификатор приложения на телефоне определяется
   им, а не названием; файлы приложения привязаны к нему. Этот файл в `.gitignore`,
   его значение не публикуется.
3. Для подписи релиза добавить в тот же файл `signing.keystore`,
   `signing.storePassword`, `signing.keyAlias`, `signing.keyPassword`. Без них
   релизная сборка остаётся неподписанной.
4. Требуется: JDK 17+, Android SDK API 35.
5. Сборка: `Run app` в Android Studio, либо
   `./gradlew.bat :app:assembleDebug` (debug), `:app:assembleRelease` (релизный APK),
   `:app:test` (юнит-тесты), `:app:signingReport` (отпечатки ключей).

Файл `secrets.properties` читается как UTF-8: свойства по умолчанию читаются в
ISO-8859-1, и кириллица в пути к ключу превращается в недопустимые символы.

## Что реализовано

**Экран A1 («Тренировка», нет активной сессии)** — по мокапу точно:
заголовок, дата сегодня, три счётчика (последняя тренировка / за 30 дней /
всего), акцентная кнопка «Начать тренировку», таб-панель из пяти иконок
(гантель, календарь, рука с бицепсом, человечек, шестерёнка), индикатор активной
вкладки — акцентная линия над иконкой.

Счётчики — кнопки перехода в Журнал (B1):
- «Последняя тренировка» — детали (B2) этой тренировки; «← Журнал» возвращает
  на A1. Если тренировок нет (значение «—»), строка некликабельна.
- «За 30 дней» — Журнал с фильтром «Месяц» (30 дней — счётчик и фильтр совпадают).
- «Всего тренировок» — Журнал с фильтром «Всё».
«Неделя» и «Год» остаются только в журнале.

**Рабочий цикл записи**
- A2/A3/A3a: сессия, блоки упражнений, bubble-подходы. Блок свёрнут в одну строку
  (миниатюра, название): подходы и тоннаж в свёрнутом виде не
  показываются; тап по строке (`testTag block_row`) переключает раскрытие у
  активного и у завершённого блока; подход тап по строке не добавляет. Активный блок
  по умолчанию раскрыт: поля «Повторы»/«Вес» (54 px), вес подставляется из
  последнего подхода этого упражнения — акцентная рамка поля, кнопки «Добавить
  подход» и «Завершить упражнение». Он сворачивается тем же тапом по строке в ту же
  однострочную запись, акцентная рамка сохраняется — по ней видно текущее
  упражнение; в свёрнутом виде поля, кнопки и чипы скрыты, введенные значения
  полей сохраняются, добавление подхода раскрытие не меняет. Раскрытие не
  сохраняется между запусками: при восстановлении сессии (перезапуск
  приложения) активный блок раскрыт, завершённые свёрнуты. Карточка упражнения
  из тренировки не открывается — она доступна из деталей журнала и списка
  мышцы. «↻» стоит
  внутри раскрытого блока, из сжатой строки уходит; только на последнем
  завершённом блоке при отсутствии активного, тап по ней делает блок активным и
  раскрывает его. У упражнения без дополнительного веса поля «Вес» нет,
  «Повторы» на всю строку, подставление веса не работает; чип такого подхода —
  «12 повт.» (весовые остаются «5 × 85 кг»).
- A3b: правка подхода — тап по чипу открывает диалог с полями «Вес» и «Повторы»,
  кнопками «Сохранить», «Удалить», «Отмена». У упражнения без веса в диалоге
  только «Повторы». Чипы кликабельны в раскрытом активном блоке и в раскрытых
  завершённых блоках текущей сессии; в свёрнутом блоке чипов не видно, блок
  раскрывают тапом по строке. «Удалить» убирает подход;
  если удалён последний подход блока — показывается A6. Тоннаж пересчитывается
  реакльно (Room-флоу). Журнал прошлых тренировок остаётся read-only.
- A3k: комментарии тренировки и упражнения. Строка комментария тренировки — над
  блоками, комментарий упражнения — под чипами раскрытого блока (в свёрнутом
  блока его нет). Написанный комментарий виден без диалога; пустой показан подсказом
  «Добавить комментарий» — текста комментария строка не показывает. Тап по строке
  открывает диалог (testTag `workout_comment`, `block_comment`, поле `comment_input`,
  счётчик `comment_counter`): поле, счётчик «N / 250», кнопки «Сохранить», «Удалить»,
  «Отмена». Лимит 250 знаков: 251-й не принимается, поле показывает усечённый текст.
  «Удалить» очищает комментарий; пустое поле при сохранении записывает отсутствие.
  Правка разрешена в любой момент: в текущей тренировке (A3) и в истории (B2).
- A3l: лист истории упражнения. Иконка «i» — оранжевый контур с оранжевой «i»,
  правый край строки; только в раскрытом
  активном блоке (testTag `exercise_info`), в сжатой строке её нет. Тап открывает
  нижний лист (`exercise_info_sheet`): последние 3 завершённые тренировки с этим
  упражнением, текущая сессия не показывается; порядок по дате, свежая сверху.
  Строка листа (`info_session`) — дата, bubble-подходы упражнения (`info_chip`),
  комментарий упражнения под чипами (`info_comment`); у тренировки без комментария
  строки нет. Упражнение не выполнялось — текст «Данных о прошлых тренировках нет».
  Оранжевый (`info`) — цвет информационных действий, только для иконки «i», акцент
  остаётся основным. Лист закрывается свайпом, тапом вне листа и «Назад»; «Назад»
  закрывает лист, приложение не сворачивается. Стрелка сворачивания из строки
  блока убрана: строка — миниатюра, название и иконка «i» в активном раскрытом
  блоке; тап по строке переключает раскрытие без поворота.
- A4: выбор упражнения — чипы «Все» (по умолчанию) и шести областей, поиск по
  названию и по мышце, тап возвращает активным блоком. Скрытые упражнения
  («Скрытое» на экране «Мышцы») в список выбора не попадают.
- A5: подтверждение завершения — только при наличии упражнений; пустая сессия
  завершается без подтверждения и не создаёт запись.
- A6: «Подходов нет» — «Завершить без записи» удаляет блок, «Продолжить» оставляет блок активным и раскрывает его.

**Журнал (B1/B2)**
- Chip-фильтр периода (Неделя/Месяц/Год/Всё), список по датам: число упражнений
  и общий вес (Σ вес×повторы). Упражнения без дополнительного веса не влияют на
  тоннаж (вес 0); тренировка только из упражнений без веса показывает 0 кг.
  Счётчики A1 («За 30 дней», «Всего тренировок») считают такие тренировки обычными.
- Под датой — основные мышцы упражнений тренировки («грудь · широчайшие»),
  порядок по каталогу (область, id), дубли убраны; по ним видно, чем тренировались.
  Над строкой мышц — комментарий тренировки (testTag `journal_comment`), обрывается
  многоточием (2-3 строки), полный текст — в деталях и диалоге; пустого комментария
  в строке журнала нет.
- Детали read-only по составу: блоки с подходами, тап по блоку открывает карточку
  упражнения. Чипы без килограммов у упражнений без веса («12 повт.»).
  Комментарий — исключение из read-only: строка комментария тренировки над блоками
  (`detail_comment`), комментарий упражнения под чипами (`detail_block_comment`),
  тап по строке открывает тот же диалог, правка из истории разрешена.
- Удаление тренировки с подтверждением; после удаления запись снимается со стека
  навигации, нижняя таб-панель возвращается, активен таб «Журнал».
  Подходы в прошлые тренировки не добавляются.
- Правка значения подхода (B2) не реализована: содержимое диалога спецификацией
  не утверждено.

**Мышцы (C1)**
- Аккордеон областей: чипы мышц, упражнения выбранной мышцы, «Добавить упражнение».
- Открытая область и выбранная мышца сохраняются весь запуск приложения: возврат из
  карточки, формы, другой вкладки аккордеон не сворачивает — пользователь видит,
  где произошло изменение. Повторное нажатие на заголовок сворачивает область;
  при запуске приложения всё свёрнуто.
- Иконка глаза справа в строке упражнения: тап скрывает упражнение, иконка
  становится зачёркнутым глазом, упражнение перемещается в блок «Скрытое» своей
  группы. Блок по умолчанию свёрнут, раскрывается по тапу по слову «Скрытое»,
  свёрнут снова, когда скрытых не осталось. Тап по зачёркнутому глазу возвращает
  упражнение в общий список.
- Сортировка по алфавиту в общем списке и в блоке «Скрытое» (`COLLATE NOCASE`).

**Карточка упражнения (C3, C3a)**
- Карточка: фото (тап — лист источника C3a: «Снять фото камерой», «Выбрать из
  галереи», «Удалить фото»), название, мышцы цветом (основные/вторичные), график
  максимального рабочего веса по датам (окно 20 точек, листается свайпом),
  «История упражнения» — тренировки, содержащие это упражнение, тап открывает
  детали тренировки.
- У упражнения без дополнительного веса под фото подпись «Без дополнительного веса»
  (read-only), график — максимальные повторы по датам с подписями оси в повторах,
  чипы истории — «12 повт.».
- Карандаш в правом верхнем углу открывает форму редактирования.
- «Удалить упражнение» — мягкое удаление с подтверждением: записи журнала, подходы,
  график и история сохраняются; после подтверждения карточка закрывается и происходит
  возврат на прежний экран.

**Форма упражнения (C2, C3c)**
- Название, фото, «Основные мышцы» и «Вторичные мышцы» секциями по мокапу C3c:
  чипы уже выбранных мышц (тап снимает выбор) и чип «+ добавить», открывающий лист
  выбора мышцы; лист показывает мышцы, ещё не выбранные в этой секции.
- Строка под названием — тоггл «Упражнение без дополнительного веса».
- Мышца не может быть одновременно основной и вторичной.
- «Сохранить» закрывает форму и возвращает на прежний экран.

**Изменения (E1–E4)**
- Список групп (название, число фото, дата последнего); четыре группы заданы
  приложением («Вид спереди», «Вид сзади», «Вид слева», «Вид справа»), пользователь
  добавляет свои.
- E2: сетка фото по дате добавления (последнее сверху), дата в левом верхнем углу
  плитки; долгий тап выделяет фото.
- Кнопки при выделении, все одного размера и равной ширины: при одном выбранном —
  «Удалить» и «Отменить»; при двух и более — «Сравнить», «Удалить», «Отменить».
  «Добавить» скрыта, пока есть выделение; «Отменить» сбрасывает выделение.
- Удаление фото требует подтверждения: «Вы точно хотите удалить N изображений?»
  (число склоняется).
- «Добавить» — нижний лист источника: камера или галерея; файл копируется в
  `filesDir/photos`.
- E3: просмотр — снимок на весь экран, дата в левом верхнем углу, свайп листает
  по дате добавления; E4: сравнение выделенных фото — лента миниатюр, свайп и тап
  по миниатюре листают, порядок выбора пользователя не влияет.

**Настройки (D1)**
- Тема: тёмная, светлая или как в системе — работает.
- Версия приложения (`BuildConfig.VERSION_NAME`).
- Экспорт, импорт архива — серые строки фазы 2.
- «Проверка обновлений» — активная строка. По тапу приложение один раз
  обращается к релизной стороне GitHub, сравнивает номер версии, скачивает
  APK во внутренний каталог (`cacheDir/updates`) и передаёт его системному
  установщику через FileProvider. Результат — диалог: «Версия актуальна»,
  «Сеть недоступна», «Ответ не читается», «Есть версия <тег>» с датой
  публикации и описанием релиза, «Скачивание», «Скачивание не удалось»,
  «APK скачан». Кнопки диалога: «Скачать и установить», «Позже»,
  «Повторить», «Открыть настройки», «Повторить установку», «Закрыть».
  Подпись строки показывает состояние: текущая версия, «проверка…», номер
  новой версии, «актуальна», «сеть недоступна», «нет ответа», «скачивание…»,
  «не скачалось», «готов», «разрешение», «вручную». Диалог закрывается,
  результат остаётся в подписи строки: повторная проверка — тот же тап.
- Установка требует разрешения на установку из приложения; без него диалог
  ведёт в системные настройки и позволяет повторить установку после возврата.
- Отладочную сборку релизная версия не обновит (ключи подписи разные):
  в отладочной сборке предупреждение показывается, установку не запускаем.

**Каталог**
- Посев базы: 6 областей, 15 мышц, 46 базовых упражнений с разметкой первичных и
  вторичных мышц. Свой список — открытый вопрос спецификации; каталог редактируется
  в `Seed.kt`, посев выполняется при создании базы.
- Упражнения без дополнительного веса (подтягивания, брусья, отжимания, выпады,
  пресс и подобные) помечаются в посеве сразу; пользователь переключает тоггл вручную.
- Переход базы с версии 1 на 2: поле `isHidden` у упражнения (`MIGRATION_1_2`).
- Переход базы с версии 2 на 3: поле `isBodyweight` у упражнения (`MIGRATION_2_3`);
  старые тренировки не портятся, записанные подходы остаются как записаны.
- Переход базы с версии 3 на 4: поле `comment` у блока упражнения (`MIGRATION_3_4`);
  старые блоки остаются без комментария, комментарии тренировки не затронуты.

## Решения, заложенные в основу

- Офлайн, никаких разрешений, никаких сетевых обращений.
- Отступы системных баров (issue #18): `enableEdgeToEdge()` в `MainActivity`,
  бары прозрачные, цвет баров в `themes.xml` совпадает с фоном приложения, фон
  Scaffold продолжается под бары. Таб-панель в слоте `bottomBar` применяет
  `navigationBarsPadding()`, вложенные экраны получают отступ через
  `contentPadding` Scaffold, лист источника фото — от `ModalBottomSheet`.
  При 3-кнопочной навигации панель встаёт над кнопками, при жестовой inset = 0
  и панель прижата к нижней границе. Правило: любой новый экран, панель,
  диалог или лист обязан применять отступы системных баров, чтобы последний
  элемент контента оставался видимым и кликабельным.
- Навигация — стек экранов: вкладки добавляются, а не заменяют текущий; вложенные
  экраны (карточка, форма, детали) снимаются, «Назад» возвращает на предыдущее окно;
  двойной «Назад» сворачивает приложение.
- Фото: путь к файлу в `filesDir/photos`, файл копируется при импорте; удаление
  упражнения мягкое (`isDeleted`), записи журнала остаются. Скрытие упражнения —
