# Android-приложение: учёт прогресса в тренажёрном зале
Спецификация требований. Зафиксировано обсуждением, 19.11.2026.

## 1. Назначение
Личное приложение для ведения журнала тренировок и наблюдения прогресса:
сколько и что поднято по каждому упражнению, и как меняются рабочие веса со временем.
Офлайн, без аккаунта, данные только на устройстве.

## 2. Зафиксированные решения
| Область | Решение |
|---|---|
| Платформа | Только Android |
| Стек | Kotlin + Jetpack Compose, локальная БД Room |
| Минимальная версия | Android 8 (API 26) |
| Единицы | Только килограммы |
| Язык интерфейса | Только русский |
| Данные | Локально, без аккаунта; экспорт CSV/JSON (фаза 2) |
| Библиотека упражнений | Встроенный каталог по группам мышц + свои упражнения |
| Мышцы | В MVP текстовый фильтр по группам + поля первичной/вторичной мышцы; фаза 3 — интерактивная 2D-векторная карта тела (спереди/сзади), 3D не используем |
| Ввод во время тренировки | Быстрая запись: минимум тапов, вес по умолчанию = прошлый подход |
| Прогресс | График веса/повторов по упражнению; сводка по неделям/месяцам (тоннаж); сравнение периодов |
| Рекорды | Лента PR + авторасчёт 1ПМ (Эпли/Бруки), расчёт рабочих весов от 1ПМ |
| Программы | Готовые шаблоны PPL, 5×5, GZCLP + свои программы, отмеченные выполненные дни |
| Таймер | Отдых между подходами |
| Интерфейс | Тёмная тема, крупные элементы для работы в зале |
| Виджет | Виджет на главном экране (последняя тренировка, быстрый вход) |
| Не нужно | Уведомления-напоминания, импорт из CSV/Excel, социальное, облачная синхронизация |
| Выпуск | Личное приложение, без публикации в магазин приложений |
| Объём первой версии | Максимально узкий: журнал и один график |
| Ключ подписи | Один релизный ключ, созданный в первый день; хранится локально, в репозиторий не попадает |
| Релизы и обновления | GitHub Releases с APK; репозиторий публичный; установка вручную (браузер/файловый менеджер) или `adb install -r`; проверка обновлений внутри приложения — фаза 2 |

## 3. MVP (релиз 1) — узкий старт
**Входит**
1. Каталог упражнений: встроенный набор базовых упражнений по группам мышц; у упражнений свободных весов и собственного веса — иллюстрации из генератора, у машин — фото пользователя. Своё упражнение создаётся из экрана Мышцы (аккордеон): название, основная и вторичные мышцы, снаряжение, фото. Миниатюры фото в блоках тренировки, в списке выбора, в аккордеоне, фото в карточке упражнения.
2. Цикл записи тренировки: сначала добавляется упражнение, затем внутри него подходы (у подходов свой вес и свои повторы), упражнение завершается явной кнопкой, затем следующее упражнение или завершение тренировки. Подход добавляется двумя тапами: значение повторов и веса (вес по умолчанию подставляется из последнего подхода этого упражнения). Завершённые блоки свёрнуты и показаны bubble-подходами; активный блок раскрыт с полями ввода.
3. Журнал: chip-фильтр периода (Неделя / Месяц / Год / Всё) и список тренировок по датам; вся история хранится, фильтр не удаляет данные; детали тренировки read-only по составу — упражнения блоками с bubble-подходами; доступно удаление тренировки. Подходы в уже записанную тренировку не добавляются: запись отражает событие, а не дополняется задним числом. Запись тренировки задним числом (забыли вести журнал) — открытое решение.
4. Один график: динамика максимального рабочего веса по датам. График листается свайпом горизонтально, окно по умолчанию 6 недель (20 тренировок при 3 в неделю), y-ось подстраивается под видимое окно; тап по точке показывает значение и дату. Под графиком блок «История упражнения» — по тренировкам: дата + bubble-подходы, тап открывает детали тренировки.
5. Мышцы: аккордеон областей, внутри открытой области конкретные мышцы chip-ами, под выбранной — её упражнения и кнопка «Добавить упражнение»; в карточке упражнения мышцы показаны цветом (основные акцентом, вторичные контуром), подписей нет; названия мышц у строк списка не подписываются.
6. Изменения: приложение задаёт группы «Вид спереди», «Вид сзади», «Вид слева», «Вид справа», пользователь создаёт свои; в группе добавление фото (камера или галерея), сетка по дате добавления, выделение долгим тапом (несколько — «Сравнить» и «Удалить», одно — «Удалить»), просмотр с свайпом по группе, сравнение выделенных фото свайпом. Дата фото показывается в левом верхнем углу. Числовые замеры (обхваты, вес тела) не входят.

**Не входит в MVP**
Программы и шаблоны, лента рекордов, расчёт 1ПМ, расчёт рабочих весов по процентам, тоннаж и сводки по неделям/месяцам, сравнение периодов, виджет, антропометрия, таймер отдыха, экспорт, уведомления, RPE/заметки, English UI, фунты, проверка обновлений внутри приложения, интерактивная карта мышц.

**Критерии готовности MVP**
- Тренировка записывается за ~20 секунд на 5 упражнений, без интернета.
- Закрытый цикл: создан, отредактирован, удалён подход; история не теряется при перезапуске.
- График строится по накопленным данным и корректно выглядит при 1–2 тренировках.
- Данные сохраняются между версиями приложения: установка новой версии поверх старой не трогает журнал. Удаление приложения удаляет базу, поэтому перед удалением нужен экспорт (фаза 2) или штатный резерв устройства.

## 4. Экраны MVP
**Правило навигации.** Нижняя таб-панель только на пяти верхних экранах: Тренировка, Журнал, Мышцы, Изменения, Настройки. Пункты таб-панели — иконки без текста: названия пунктов не влезают в четыре колонки на узком телефоне (иконки: гантель — Тренировка, календарь — Журнал, рука с бицепсом — Мышцы, человечек — Изменения, шестерёнка — Настройки). Названия пунктов не влезают в пять колонки на узком телефоне, поэтому текст в таб-панели не показываем. Иконка Мышц — найденный пользователем векторный путь из SVG Repo (viewBox 512, залитый путь), вставлен в мокап как есть; человечек занят разделом «Изменения». Провенанс иконки записывать при публикации: SVG Repo. Детальные экраны — вложенные, без таб-панели, с заголовком возврата («← Журнал», «← Мышцы»). Карточка упражнения — деталь, открывающаяся из Мышц, из деталей тренировки и из блока тренировки; активная вкладка на ней не показывается.

**Раздел «Тренировка»**
A1. **Нет активной сессии** — кнопка «Начать тренировку»; ниже счётчики, которые реально меняются: дата последней тренировки, число тренировок за 30 дней, всего тренировок. Счётчиков каталога и своих упражнений нет: это статика, она неинтересна. Тоннаж и сводки — фаза 2.
A2. **Сессия начата, упражнений нет** — текст пустого состояния, кнопки «Добавить упражнение» (акцентная) и «Завершить тренировку» (контурная) доступны.
A3. **Активная сессия** — блоки упражнений в порядке добавления, у каждого миниатюра фото; подходы везде bubble-подходами, отдельных строк подходов нет. Активный блок раскрыт: bubble-подходы, поля Повторы и Вес (вес подставлен из последнего подхода этого упражнения, акцентная рамка), кнопки «Добавить подход» и «Завершить упражнение» (обе — визуальные кнопки). Завершённые блоки свёрнуты: без текстового статуса «завершено» и без числа подходов, подходы видны bubble-подходами. Пока текущее упражнение не завершено, кнопки «Добавить упражнение» и «Завершить тренировку» скрыты: цикл — один блок за раз.
A3a. **Нет активного упражнения (все завершены)** — нижние кнопки «Добавить упражнение» и «Завершить тренировку» доступны; иконка «↻» (без текста) показывается только на последнем завершённом блоке и только когда активного упражнения нет. Тап по ней делает этот блок активным, чтобы продолжить после случайного завершения.
A4. **Выбор упражнения** (вложенный из A2/A3) — акцентный выбор области, список упражнений (миниатюра, название); тап возвращает активным блоком. Поиск находит и по названию, и по мышце: набор «бицепс» даёт упражнения, где бицепс основной или вторичный. Кнопки создания упражнения нет.

**Раздел «Журнал»**
B1. **Журнал** — chip-фильтр периода (Неделя / Месяц / Год / Всё) и список тренировок по датам: дата крупно, под ней строка — слева число упражнений, справа общий вес тренировки по правому краю; тап открывает детали. Хранится вся история, фильтр меняет только список.
B2. **Детали тренировки** (вложенный из B1) — упражнения блоками с миниатюрой и bubble-подходами. Read-only по составу: подходы в записанную тренировку не добавляются, значения записанных подходов не правятся. Внизу «Удалить тренировку» с подтверждением.

**Раздел «Мышцы»**
C1. **Мышцы (akкордеон)** — заголовки akкордеона: области (Грудь, Спина, Плечи, Руки, Ноги, Корпус). Внутри открытой области конкретные мышцы chip-ами (Бицепс, Трицепс, Предплечья…), под выбранной мышцей — её упражнения; в конце списка кнопка «Добавить упражнение». Открыта одна область, выбрана одна мышца. Названия мышц у строк упражнений не подписываем: пользователь выбрал мышцу и знает, что смотрит её упражнения. Создание упражнений доступно только отсюда.
C2. **Новое упражнение** (вложенный из C1) — фото (тап на плюс → лист C3a), название, основные мышцы (bubble акцентным, «+ добавить», можно несколько), вторичные мышцы (bubble серым, «+ добавить»), «Сохранить». Поля «Снаряжение» нет.
C3. **Карточка упражнения** (из C1, из B2, из A3) — фото с плюсом в круге: тап открывает лист C3a; цвет мышечных групп без подписей (основные акцентом, вторичные контуром); график максимального веса по датам — листается свайпом, окно 6 недель, заголовок графика без поясняющего текста; блок «История упражнения» по тренировкам: дата + bubble-подходы, тап открывает детали тренировки. Карандаш в правом верхнем углу — редактирование (C3c), кнопка «Удалить упражнение» внизу (диалог C3b).
C3b. **Диалог удаления упражнения** — подтверждение. Записи тренировок, подходы, график и история упражнения не удаляются: упражнение помечается isDeleted и скрывается с интерфейса.
C3c. **Редактирование упражнения** (по карандашу) — та же форма, что при создании: фото, название, основные и вторичные мышцы, «Сохранить». Поля заполнены текущими значениями.
C3a. **Нижний лист источника фото** — камера / галерея / удаление; выбранный файл копируется в каталог приложения.

**Раздел «Изменения»**
E1. **Список групп** — строки групп: название, число фото, дата последнего; кнопка «Новая группа». Приложение задаёт четыре группы: «Вид спереди», «Вид сзади», «Вид слева», «Вид справа»; свои группы пользователь создаёт сам.
E2. **Группа** — сетка плиток по дате добавления, последнее сверху; дата фото в левом верхнем углу плитки; «Добавить фото» открывает тот же нижний лист камеры и галереи.
E2a. **Режим выделения** — долгий тап выделяет фото (akцентная рамка и галочка). При нескольких выделенных — кнопки «Сравнить» и «Удалить»; при одном выделенном — только «Удалить».
E3. **Просмотр** — по тапу на фото снимок на весь экран, дата в левом верхнем углу, свайп листает фото группы по дате добавления.
E4. **Экран «Сравнить»** — снимок на весь экран с датой в левом верхнем углу, лента мини-изображений выделенных фото внизу; свайп по снимку и тап по миниатюре листают; порядок по дате добавления, порядок выбора пользователем не влияет.
E5. **Новая группа** — одно поле названия и «Сохранить».

**Раздел «Настройки»**
D1. **Настройки** — Тема (тёмная / светлая / как в системе), Экспорт (архив: данные + фото; фаза 2, серый), Импорт архива (фаза 2, серый), Проверка обновлений (фаза 2, серый), О приложении (версия). Настроек «Единицы» и «Свои упражнения» нет.

A5. **Диалог подтверждения завершения тренировки** — показывается, только если за сессию добавлено хотя бы одно упражнение: заголовок «Завершить тренировку?» по центру, кнопки «Завершить» и «Отмена». Поясняющий текст внутри диалога нет. Если упражнений нет, завершение идёт без подтверждения, и запись в журнал не создаётся: пустая сессия не порождает запись.
A6. **Диалог «Подходов нет»** — при «Завершить упражнение» с нулём подходов: заголовок «Подходов нет» по центру, кнопки «Завершить без записи» и «Продолжить упражнение». Поясняющего текста нет. Подтверждение — упражнение в сессию не записывается (записей о подходах нет); «Продолжить упражнение» оставляет блок активным.

Прочие диалоги: подтверждение удаления тренировки, подтверждение удаления упражнения — содержимое не утверждено.

Ограничение по интерфейсу: крупные элементы, минимум мелкого текста, тёмная тема по умолчанию; всё управляется одной рукой.
Правила разметки (по мокапам):
- Название упражнения переносится максимум в две строки; многоточие только если длиннее двух строк; обрезание в одну строку запрещено, потому что «Жим гантелей на наклон…» не различает варианты.
- Значения веса и повторов — правая колонка фиксированной ширины 86 px, вертикально по центру; они не «южатся» у края.
- Поля ввода повторов и веса равной шириной, занимают всю строку, высота 54 px.
- Подставленное значение (вес из прошлого подхода) обозначается акцентной рамкой поля; текстовая подпись не нужна.
- Плюс в круге рисуется векторно и центрируется по кругу; текстовый символ «+» не используется, он не встаёт в центр.
- Под фото подписание один текст «Фото»: длинные пояснения («фото тренажёра · тап → из галереи или снять», «нажмите, чтобы установить или заменить») не показываем; действие объясняет нижний лист по тапу.
- Числа подходов (1 подход, 2 подхода, 3 подхода) нигде не подписываем: подходы видны bubble-подходами. Слово «завершено» не показываем: завершённый блок свёрнут и akцентная рамка снята.
- Кнопки: акцентная (основное действие) и контурная (второстепенное), высота 52 px; таб-бар внизу, индикатор активной вкладки — акцентная линия над текстом.
- Названия групп мышц только кириллицей: калька «Кор» не используется, группа называется «Корпус».

## 5. Модель данных (сущности)
- **Exercise**: id, название, основные мышцы (список id Muscle, акцентный цвет), вторичные мышцы (список id Muscle, серый цвет), тип (базовое/своё), изображение (путь к локальному файлу), isDeleted. Поле снаряжения в MVP нет (потенциально фаза 3).
Картинка обязательна: пользователь узнаёт упражнение по фото тренажёра, название он может не помнить. В карточке и в форме фото отображается плюсом в круге (плюс центрируется векторной отрисовкой), под фото только подпись «Фото»; тап открывает нижний лист: «Снять фото камерой», «Выбрать из галереи», «Удалить фото». Выбранное или снятое изображение копируется в каталог приложения (файлы приложения не удаляются при обновлении версии); в базу Room идёт только путь.
Хранение фото (зафиксировано): основной каталог — приватный каталог приложения `filesDir/photos`, он переживает обновления. Отдельная папка в DCIM обсуждается как фаза 2: запись в общий DCIM требует MediaStore, фото становятся видны в галерее, но их труднее резервировать. Решение по DCIM — открытое.
Удаление упражнения — мягкое: в Room ставится isDeleted, запись и связанные данные (WorkoutExercise, SetEntry, фото, график) сохраняются. Такое упражнение пропадает из аккордеона, списка выбора упражнения, каталога; карточка, график и история продолжают открываться из журнала, потому что блоки тренировок ссылаются на ту же запись упражнения.
Источники картинок каталога (зафиксировано):
- Для упражнений на машинах конкретного зала — фото пользователя: обобщённая генерация не совпадает с машиной в зале, узнавание работает только по реальному снимку.
- Для свободных весов и собственного веса (жим лёжа, приседания, подтягивания, планка) — иллюстрации, собранные генерацией: обобщённая поза узнаваема, стиль держится одним промптом.
- Условия генератора записывать как provenance: сервис, тариф, дата, промпт. Права на результат определяются условиями сервиса; для личного приложения это обычно разрешено, проверка по факту использования.
- **MuscleArea**: id, название области (Грудь, Спина, Плечи, Руки, Ноги, Корпус). Заголовки аккордеона и chip-фильтры в выборе упражнения.
- **Muscle**: id, название конкретной мышцы, area_id, области схемы тела (фаза 3). Рабочая единица фильтра и аккордеона. Предварительный список: Грудь, Широчайшие, Большая круглая, Бицепс, Трицепс, Предплечья, Передняя дельта, Средняя дельта, Задняя дельта, Квадратичные, Бицепс бедра, Икры, Ягодицы, Пресс, Поясница — уточняется вместе с каталогом (открытый вопрос). Названия только кириллицей; калька «Кор» не используется, область называется «Корпус».
- **WorkoutSession**: id, дата/время, комментарий.
- **WorkoutExercise** (фаза 1): id, session_id, exercise_id, порядок упражнения в сессии, статус (не начато / в работе / завершено).
- **SetEntry**: id, workout_exercise_id, порядок подхода внутри упражнения, вес (кг), повторы, (позже: отдых, RPE, заметка).
- **PersonalRecord** (фаза 2): exercise_id, тип рекорда, значение, дата.
- **ChangeGroup** (раздел «Изменения»): id, название, дата создания, признак предустановленной группы. Предустановленные: «Вид спереди», «Вид сзади», «Вид слева», «Вид справа».
- **ChangePhoto**: id, group_id, изображение (путь к локальному файлу в `filesDir/photos`), дата съёмки.
- **Program** (фаза 3): id, название, дни, упражнения, подходы, целевые повторы.

Индекс по (exercise_id, date) — для графиков; при удалении тренировки связанные подходы удаляются каскадно.
Разметка первичной и вторичных мышц — часть данных каталога: ~40–60 упражнений, ~200 строк. Ошибки разметки видны сразу (жим лёжа: грудь первично, трицепс и передняя дельта вторично; подтягивания: широчайшие первично, бицепс и предплечья вторично).

## 6. Расчёты (после MVP)
- **Тоннаж**: сумма (вес × повторы) за тренировку, за неделю/месяц.
- **1ПМ**: Эпли `вес × (1 + повторы/30)`; Бруки для повторов ≤ 10; отображать как оценку, не как рекорд.
- **Рабочие веса от 1ПМ**: проценты 65/70/75/80/85, подсказ веса для подхода.
- **Сравнение периодов**: средние рабочие веса и тоннаж за последние 3 месяца против предыдущих 3.

## 7. Фазы
- **Фаза 1 (MVP)**: журнал, быстрый ввод, каталог упражнений, один график, текстовый фильтр по мышечным группам.
- **Фаза 2**: лента PR + 1ПМ, тоннаж и сводки по неделям/месяцам, сравнение периодов, таймер отдыха, экспорт и импорт архива (данные + фото), проверка обновлений из GitHub Releases по кнопке.
- **Фаза 3**: интерактивная карта мышц, программы (шаблоны PPL, 5×5, GZCLP и свои), расчёт рабочих весов от 1ПМ, виджет, антропометрия (вес тела, замеры).

## 8. Карта мышц (фаза 3)
**Что это**
Интерактивная векторная схема тела: вид спереди и вид сзади, переключение табом. ~25–30 векторных областей, у каждой id, совпадающий с id мышечной группы. Обе функции работают на одном механизме:
- выбрано упражнение → область первичной мышцы — сильный цвет, вторичные — слабый, остальные — нейтральный;
- нажата область → список упражнений, где эта мышца первичная или вторичная.
Карта визуализирует таблицу данных, отдельной логики подсветки нет. Анимация смены подсветки средствами Compose.

**Технически**
- Области описаны путями SVG; путь → `android.graphics.Path` через `PathParser` из androidx vectordrawable; отрисовка в Compose Canvas.
- Проверка нажатия: `PathRegion` из androidx.graphics (библиотека для проверки «точка внутри пути»). Точное название API и минимальный уровень проверить при реализации — сегодня подтвердить не удалось.
- 3D-модель не используется: нужен 3D-ассет, рендер через OpenGL/Vulkan в AndroidView, вопросы лицензирования; работа в ~10 раз больше, пользу для журнала весов не даёт. Сегментированная 2D-схема закрывает задачу.
- Источник схемы: открытую SVG-карту с пригодной лицензией найти не удалось. Решили рисовать упрощённую схему самим (стилизованная фигура, ~25 областей) — нет лицензионного риска, анатомическая точность журналу не нужна.

## 9. Технические требования
- Kotlin, Jetpack Compose, ViewModel + Flow, Room (SQLite), одна локальная база.
- Минимальный API 26, target — последний стабильный API.
- Офлайн: никаких сетевых зависимостей, никаких аккаунтов и аналитики.
- Никаких разрешений в MVP; позже — нужные для видажета, экспорта, и `REQUEST_INSTALL_PACKAGES` для проверки обновлений (фаза 2).
- Локализация: только русский, единицы — кг; форматирование чисел с одним знаком после запятой.
- Тема: Material 3, тёмная по умолчанию, светлая, режим «как в системе» — настройка в Настройках.
- Фото: съёмка через системную камеру (ACTION_IMAGE_CAPTURE), выбор из галереи (GetContent), файл копируется во внутренний каталог приложения; отдельных разрешений на камеру и хранилище не нужно; изображения показываются через Coil.

## 10. Установка, релизы и обновления
**Как приложение попадает на телефон**
- Релизная сборка подписывается релизным ключом (файл `keystore`), `versionCode` растёт при каждой сборке, `applicationId` не меняется.
- Релиз 1: APK собирается локально в Android Studio; установка через `adb install -r` (USB, отладка по USB) или копированием APK в телефон и открытием в файловом менеджере. Один раз выдаётся разрешение на установку из неизвестных источников для приложения-источника (Android 8+, модель API 26).
- Возможная реакция Play Protect на APK из стороннего источника — предупреждение снимается вручную.

**GitHub Releases (релиз 1)**
- Репозиторий, тег (`v1.2.0`), прикреплённый файл APK; прямая ссылка вида `github.com/владелец/репозиторий/releases/download/тег/app.apk`, страница `/releases/latest` ведёт на новейший релиз.
- GitHub APK не подписывает: сборка и подпись только локально, ключ не размещается в репозитории и не кладётся в секреты Actions. Публикация командой `gh release create v1.2.0 app-release.apk`.
- Сборка APK на GitHub Actions (действия build-and-release-apk, github-action-release-apk) — не используем, потому что требует ключа в репозитории.
- Репозиторий публичный — зафиксировано. Причина: проверка обновлений внутри приложения работает без токена (публичные релизы доступны через GitHub API); приватный потребовал бы встроить токен чтения в приложение. Следствия: APK и исходный код доступны всем; это безопасно, ключ подписи остаётся локально, чужая сборка не установится поверх нашей из-за разной подписи.

**Условия, при которых установка новой версии = обновление с сохранением журнала**
1. Имя пакета (`applicationId`) то же.
2. APK подписан тем же ключом, что установленный.
3. `versionCode` не меньше установленного (меньшая версия блокируется как понижение).
Сохраняются: база Room, настройки, выданные разрешения, ярлык.
Когда обновлением не является: другой ключ подписи (нужно удаление, журнал теряется); приложение удалено заранее; изменённое имя пакета (рядом появляется второе приложение).

**Правило про отладочные сборки**
Отладочный ключ отличается от релизного: отладочную сборку нельзя обновить релизной. Практика: отладочные сборки — на эмулятор; на телефоне только релизные сборки под одним ключом.

**Проверка обновлений внутри приложения (фаза 2)**
- Приложение по кнопке обращается к GitHub API `api.github.com/repos/владелец/репозиторий/releases/latest`, сравнивает версию, скачивает APK в свой внутренний каталог (Android 10+ требует файл для установки в каталоге приложения, используется FileProvider) и запускает системный установщик; нужно разрешение `REQUEST_INSTALL_PACKAGES`.
- Это единственное сетевое обращение в приложении: один запрос по нажатию кнопки, без аккаунта, без передачи данных журнала. Требование офлайна остаётся в силе.
- Стороннее приложение-обновлятор (GitHub-Store) — не используем: его требования к именам ассетов и правилу выбора файла не проверены; самообновление в самом приложении короче и не зависит от третьей стороны.
- Готовые библиотеки самообновления (APK-MultiUpdate, Flutter github_release_apk_updater) — не подходят напрямую, но задают шаблон логики.

**Перенос данных**
На новый телефон: архив (JSON с данными + папка фото), импорт читает тот же архив; CSV/JSON по отдельности фото не переносят, поэтому экспорт сделан архивом. До появления экспорта приложение не удаляем, только обновляем; штатный резерв устройства тоже подходит.
