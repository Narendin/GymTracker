# Постановка PR GymTracker

PR закрывает issue: первая строка описания — `Closes #N`, остальной текст
по-русски. PR без issue не создаются. Репозиторий
`github.com/Narendin/GymTracker`, базовая ветка `Master`. Порядок git
целиком — `skills/git-workflow/SKILL.md`; здесь только постановка PR.

## Железные правила

1. **Первая строка описания — `Closes #N`.** GitHub связывает issue и
   закрывает её при мерже только по английскому ключевому слову. Остальной
   текст — по-русски.
2. **Заголовок PR — название issue, по-русски.**
3. **Тело PR — из файла, прочитанного в UTF-8.** PowerShell 5.1 читает
   файлы по умолчанию в CP1251, и `Get-Content -Raw` без `-Encoding utf8`
   превращает кириллицу в искажение кодировки (проверено: PR ушёл в GitHub
   искажённой кодировкой).
   Проверка после отправки обязательна.
4. **Секретов в тексте нет.** `applicationId`, путь к ключу, alias, пароли
   и отпечатки ключей не пишутся; в тексте — `<applicationId>`,
   `<путь к ключу>`, `<alias>`. Реальный репозиторий в URL текста PR не
   подставлять, писать `владелец/репозиторий`.
5. **Создание PR — по явному указанию пользователя.** Подготовь описание и
   спроси, не создавай PR «по завершении вехи».
6. **PR никогда не мержи сам.** Создай PR, дай ссылку — мержит пользователь.
7. **В PR — своя документация.** PR без документации по задаче не мержат:
   проверь, что в диффе есть правки всех файлов документации, описывающих
   то, что задача меняет.

## Шаг 1. Проверка перед созданием

- `& "C:\Program Files\GitHub CLI\gh.exe" auth status` — аккаунт `Narendin`,
  токен с правом `repo`.
- Ветка создана от актуального `Master`, в ней есть коммит(ы) задачи.
- `git status --short` — чисто: временные файлы (дампы uiautomator, снимки
  экранов, тело issue/PR) удалены, в коммит не идут.
- Автотесты по задаче прогнаны до коммита (`skills/run-autotests/SKILL.md`).
- Code-review диффа проведён (`code-review`).
- Номер issue записан — он нужен первой строкой описания.

## Шаг 2. Текст

Структура тела, по-русски:

```
Closes #N

одна строка: что сделано по сути

**Что сделано**
конкретные изменения по месту (экраны, функции, формат)

**Технически**
где собрано решение, новые функции, затронутые места

**Проверка**
- автотесты: сколько проверок, результат прогона (N/N прошли)
- ручная проверка: на эмуляторе/телефоне
- Документация: файлы, правки которых входят в PR

**Дополнительно** (если в коммите есть несвязанные правки)
что именно и почему в этом коммите
```

- Раздел «Проверка» обязателен: результат прогона автотестов, список
  документации. PR без своего теста на изменение кода приложения не мержат.
- Раздел «Документация» перечисляет файлы, правки которых в PR:
  `docs/STATE.md`, `docs/gym-tracker-requirements.md`, `docs/CHANGELOG.md`,
  при необходимости `docs/BUILD.md`, `docs/RELEASE.md`.
- Если коммит содержит несвязанные изменения — сказать прямо, не придумывать
  единную историю.
- Ссылки на документацию и другие issue в теле PR — можно. В коде ссылок
  быть не должно.

## Шаг 3. Отправка

- Тело писать во временный файл `pr-<тема>-body.md` в корне проекта. Файл
  в коммит не идёт и удаляется после отправки.
- Отправка:

```
$body = Get-Content -Raw -Encoding utf8 "F:\Pets\GymTracker\pr-<тема>-body.md"
& "C:\Program Files\GitHub CLI\gh.exe" pr create -B Master -H <branch> `
  -t "<Название issue по-русски>" -b $body
```

- Заголовок, переданный строкой в командной строке, кодировку не теряет;
  тело из файла — всегда с `-Encoding utf8`.
- Двойные кавычки внутри тела (например «Повторы») ломают разбор команды
  PowerShell: тело всегда из файла, не строкой.

## Шаг 4. Проверка после отправки

```
$json = & "C:\Program Files\GitHub CLI\gh.exe" pr view <N> --json title,body | ConvertFrom-Json
($json.body -split "`n")[0]
($json.body | Select-String -Pattern 'Р­|РСЏ|СЏ|Рђ' -AllMatches).Matches.Count
```

- Первая строка — `Closes #N`, вторая читается по-русски, совпадений
  искажённой кодировки — 0.
- Если кодировка искажена: `gh pr edit <N> -b (Get-Content -Raw -Encoding utf8 <файл>)`
  и повторить проверку. Заголовок править `gh pr edit <N> -t "<новый>"`.

## Шаг 5. Уборка

- `Remove-Item <файл тела>`.
- `git status --short` — чисто: временные файлы текста в коммит не попадают.
- Ссылку на PR дать пользователю:
  `github.com/Narendin/GymTracker/pull/<N>`.
- Мержит пользователь. При мерже просить оставить галочку
  «Delete branch after merging».
