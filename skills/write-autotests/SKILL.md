# Написание автотестов GymTracker

Инструментальные тесты — `app/src/androidTest/java/com/gymtracker/AppFlowTest.kt`.
Один класс, сквозной прогон от пустой базы. Прогон — `skills/run-autotests/SKILL.md`.

## Структура

- Один класс `AppFlowTest`, аннотации `@RunWith(AndroidJUnit4::class)` и
  `@FixMethodOrder(MethodSorters.NAME_ASCENDING)`.
- Методы идут по нарастанию имён: `a1_`, `b2_`, `c3_`, …, `p16_`, `p17_`.
  Порядок задаёт накопление состояния: пустая база → одна тренировка → две → три.
- Каждый метод опирается на результат предыдущего. Новый метод вставляют
  в нужное место по логике накопления, а не в конец.
- Перед прогоном данные очищают (`adb shell pm clear <applicationId>`),
  первый метод стартует с пустой базы.

## Именование методов

- Префикс — буква + номер: `a1`, `b2`, `c3`, …, `p16`, `p17`.
  Буква — группа (a = пустое состояние, b = первая тренировка, c = счётчики,
  d = фильтры, …, p = правка/удаление подходов).
- Имя метода — английское, описывает проверяемое поведение:
  `p17_deleteSetFromCompletedBlock`.
- KDoc по-русски: одна строка — что проверяется.

## testTag

- `testTag` — часть основного кода (не тестового). Объявляется как
  `const val TAG_<NAME>` рядом с компонентом, где используется.
- В тесте тег используется через `onNodeWithTag`, `onAllNodesWithTag`.
- Новый `testTag` добавляют в код приложения, ввозят в тест через import.
- Признак выбора (`selected`) — семантика, не тег: `isSelected()` / `isNotSelected()`.

## Вспомогательные функции (уже в классе)

| Функция | Назначение |
|---------|-----------|
| `displayed(text)` | Элемент с текстом виден (прокручивает, ждёт 30 с) |
| `displayedInLabel(text)` | Текст как подстрока подписи (тоннаж в строке) |
| `tapText(text)` | Тап по элементу с текстом (прокручивает, ждёт) |
| `tapTag(tag)` | Тап по элементу с тегом |
| `tapTagIndex(tag, i)` | Тап по i-му элементу с тегом |
| `tapTab(label)` | Тап по табу (contentDescription) |
| `pickExercise(name)` | Поиск + тап по первой строке выбора |
| `typeInto(tag, text)` | Очистка поля + ввод |
| `fieldHas(tag, value)` | Поле содержит значение (ждёт) |
| `fieldGone(tag)` | Поле исчезло (блок свёрнут) |
| `countTag(tag, n)` | N элементов с тегом (ждёт) |
| `counterValue(tag, value)` | Счётчик содержит значение (ждёт) |
| `exists(text)` | Текст есть в дереве (не обязательно виден) |
| `openArea(name)` | Открыть область аккордеона (с повторным тапом) |

Не создавать новых вспомогательных функций без необходимости — использовать существующие.

## Правила написания

1. **Ждать, а не проверять мгновенно.** Состояние ViewModel приходит
   асинхронно (Room на фоновом потоке). Все проверки через `compose.waitUntil(30_000)`.
2. **Прокручивать перед кликом.** Элемент под сгибом экрана не видим:
   `performScrollTo` перед `performClick` и `assertIsDisplayed`.
3. **Лист (`ModalBottomSheet`) не прокручивается.** Тап по элементу из
   видимой части листа, не ниже сгиба.
4. **Состояние ViewModel живёт между методами.** Открытая область, фильтр,
   скрытые упражнения. Первый тап по заголовку области может свернуть
   уже открытую — `openArea` это обрабатывает.
5. **Не использовать координаты.** Только текст, `testTag`, `contentDescription`.
6. **Один метод = одна проверка поведения.** Не смешивать несвязанные
   сценарии в одном методе.
7. **Не удалять существующие методы.** Новый функционал — новый метод.
   Изменение поведения — правка существующего метода.
8. **Порядок методов — по накоплению состояния.** Новый метод вставляют
   туда, где его предпосылки уже созданы предыдущими методами.
9. **Тег внутри кликабельной карточки — в неразбитом дереве.** Кликабельный
   узел сливает детей в слитом дереве: лист с тегом строки комментария
   строки журнала (`journal_comment`) там не находится, `onNodeWithTag` падает
   и `waitUntil` даёт `ComposeTimeoutException`. Проверки таких строк — через
   `tagHas`/`tagGone`, они читают `useUnmergedTree = true`.

## Что покрывать

- **Каждый исправленный баг** — метод, воспроизводящий сценарий бага
  и проверяющий корректное поведение.
- **Каждый новый/изменённый функционал** — метод, проверяющий новое
  поведение по сценарию пользователя.
- **Навигация** — после действия панель возвращается, «Назад» работает
  (одно нажатие, не предупреждение).
- **Счётчики** — пересчитываются после изменений.
- **Фильтры** — не сбрасываются после навигации.

## Проверка

- Прогон: `skills/run-autotests/SKILL.md`.
- Перед коммитом: автотесты + проверка на чистом эмуляторе.
- Юнит-тесты (`app/src/test/`) — чистые функции (форматы, плюрализация,
  посев). UI-поведение — только автотесты.
